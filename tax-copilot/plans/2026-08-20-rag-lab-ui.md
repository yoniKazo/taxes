# שיעורי בית 3 ב-UI + שיפוץ UI/UX מלא

## Context

כל עבודת ה-RAG של מטלה 3 חיה היום **רק כסקריפטי CLI** תחת [tax-copilot/src/](tax-copilot/src/) וכקבצי תוצאה תחת [tax-copilot/assignment3/data/](tax-copilot/assignment3/data/). ה-UI ב-[tax-copilot/web/](tax-copilot/web/) מכיר שני טאבים בלבד — מחשבון ובדיקות AI — ול-FastAPI **אין ולו endpoint אחד של retrieval**.

המטרה: להכניס את מטלה 3 ל-UI כטאב שלישי מלא ("מעבדת RAG"), **בנוסף** לכל מה שקיים, ובמקביל לשפץ את ה-UI/UX — שהיום הוא עמודה אחת ברוחב 960px, בלי responsive, בלי dark mode, בלי משוב על שמירה, בלי פס התקדמות להרצות שלוקחות דקות, ועם `window.alert` בשני מקומות.

התכנון נגזר מ-[HomeWork/assignment3.md](HomeWork/assignment3.md) — **מסמך המטלה עצמו**, לא רק מה-writeup — כדי שכל שבע המשימות יקבלו ייצוג ולא רק אלה שיש להן קובץ תוצאה מוכן.

### החלטות שהתקבלו מול המשתמש
1. **בחירת צ'אנקים = גם וגם** — גם פאנל קונפיגורציית אינדוקס (אילו מסמכים, chunk size/overlap, מודל embedding → בנייה מחדש), וגם סימון/ביטול ידני של צ'אנקים שאוחזרו לפני שליחה לגנרטור.
2. **מכסת LLM** — מותר חי מה-UI: retrieval (0 קריאות), שאלה בודדת (קריאה 1), שיפוט שורה בודדת (4 קריאות). **אסור** להריץ את כל מערך ההערכה מה-UI (~200 קריאות; המכסה היומית של 500 כבר נשרפה — [phaseb_run.log](tax-copilot/assignment3/data/phaseb_run.log)).
3. **שיפוץ מלא + ספריות חדשות מותרות.**
4. **כל תוצרי מטלה 3 מוצגים**, עם מנגנון להוסיף/להוריד פאנלים לפי מה שרוצים לראות.

## שני עקרונות-על

**א. לא נוגעים בתוצרי המטלה.** הקבצים תחת [tax-copilot/assignment3/](tax-copilot/assignment3/) והסקריפטים `assignment3_*.py` הם עבודה מוגשת ונמדדת. ה-UI **קורא** מהם:
- אינדקס מותאם שנבנה מה-UI נשמר ב-`assignment3/index_custom/<slug>/`, **לעולם לא** ב-`assignment3/index/` (הקנוני, שכל הסקריפטים תלויים בו). להוסיף `assignment3/index_custom/` ל-[.gitignore](tax-copilot/.gitignore) — אחרת אינדקסי FAISS בינאריים ייכנסו לגיט.
- השינוי היחיד בקוד המטלה: פרמטר אופציונלי `chunks=None` ל-`answer_with_rag_instrumented` ([rag_pipeline.py:80](tax-copilot/src/rag_pipeline.py#L80)), שמדלג על אחזור כשהצ'אנקים כבר נבחרו ידנית. אדיטיבי; ברירת המחדל לא משתנה.

**ב. הפרדת "חינם" מ"עולה קריאות" היא גבול ארכיטקטוני, לא משמעת.** [src/llm.py](tax-copilot/src/llm.py) בונה `OpenAI(...)` **בזמן import** מ-`os.environ["GEMINI_API_KEY"]` — כלומר כל מודול שנוגע בו מת בלי מפתח. לכן:

```
api/rag/artifacts.py   # קריאת קבצי תוצאה מוכנים   — 0 imports של llm
api/rag/retrieval.py   # אינדוקס, אחזור, hit-rate   — 0 imports של llm
api/rag/generation.py  # תשובה + שופטים            — import עצל של rag_pipeline/judges
```
התוצאה: **שני שלישים מהתכונה נבדקים ב-pytest בלי מפתח API בכלל**, ואי אפשר בטעות לגרור קריאת LLM למסלול שאמור להיות חינמי.

### 1.1 `api/rag/artifacts.py` — הגשת תוצרים קיימים

הכל כבר על הדיסק. הפונקציות שקוראות אותם **קיימות ולא נכתבות מחדש**: `load_eval_set` ([assignment3_build_eval_set.py](tax-copilot/src/assignment3_build_eval_set.py)), `load_scored` / `summarise` / `find_rag_worse_than_baseline` / `find_right_answer_broken_pipeline` / `worst_rag_rows` ([assignment3_evaluate.py](tax-copilot/src/assignment3_evaluate.py), [assignment3_analysis.py](tax-copilot/src/assignment3_analysis.py)), `EXPERIMENTS` ([assignment3_experiments.py](tax-copilot/src/assignment3_experiments.py)).

| Method | Path | מקור |

| GET | `/rag/eval-set` | `tax_rag_eval_set.csv` (34 שורות) + **בדיקת כיסוי הקטגוריות** של Task 2 |
| GET | `/rag/baseline` | `baseline_results.csv` + פילוח הדליים |

| GET | `/rag/per-question` | גיליון `per_question` — 34 שורות × 47 עמודות |
| GET | `/rag/sweeps` | `task6_sweeps.csv` |
| GET | `/rag/experiments` | `EXPERIMENTS` + דלתאות מכל `*_judged.json` שהושלם |
| GET | `/rag/analysis` | ממצאי (א)/(ב)/(ג) |

> `exp1` הושלם חלקית (6 מתוך 34 שורות) ו-`exp3` לא רץ כלל. ה-API מחזיר `status: partial|missing` עם `rows_judged/rows_total`, וה-UI מציג "לא הושלם" — **לא אפס ולא ממוצע חלקי**. דיווח חלקי כאילו הוא מלא הוא בדיוק סוג הכשל שהמטלה מענישה עליו.

### 1.2 `api/rag/retrieval.py` — אחזור ואינדוקס (עדיין 0 קריאות LLM)

- `get_vectorstore(index_id)` עם cache ברמת התהליך. `index_id="default"` → `assignment3/index/`.
- `preview_chunks(doc_names, chunk_size, chunk_overlap)` — `split_documents` + `enrich_section_metadata` בלבד. **בלי embedding, מיידי.** מאפשר לראות כמה צ'אנקים ואיפה הגבולות **לפני** ששורפים דקות CPU.
- `browse_chunks(index_id, doc_name?, seed?, n?)` — דגימת צ'אנקים לקריאה (Task 3).
- `retrieve(query, k, index_id, retriever, dense_weight)`.
- `build_index_with_progress(...)` — `FAISS.from_documents(batch0)` ואז `add_documents` בקבוצות של 32, כדי שיהיה פס התקדמות **אמיתי**. משתמש ב-`PrefixedEmbeddings` מ-[src/embeddings.py](tax-copilot/src/embeddings.py). כותב `meta.json` עם הקונפיג לצד האינדקס.
- `evaluate_retrieval(index_id, k, retriever, dense_weight)` — עוטף את `hit_rate_over_eval` הקיים. **0 קריאות LLM, ~10–30 שניות.** זה מה שהופך את פאנל הקונפיג מצעצוע לכלי: המטלה אומרת במפורש *"Sweep against hit-rate. It's free"*.

**שלוש מלכודות טכניות שחייבות טיפול:**

1. **`build_hybrid_retriever` מקודד קשיח את האינדקס הקנוני** — [assignment3_experiments.py:105-110](tax-copilot/src/assignment3_experiments.py#L105-L110) קורא ל-`chunks_for()` (1000/150) ול-`load_index()` (default). קריאה שלו על אינדקס מותאם תחזיר **בשקט** תוצאות מהאינדקס הלא-נכון. הפתרון: פונקציה מקבילה ב-`retrieval.py` שמקבלת `chunks` ו-`vectorstore` מפורשים; הסקריפט המקורי לא משתנה.
2. **`similarity_search_with_score` ב-FAISS מחזיר מרחק L2, לא דמיון** — קטן יותר = טוב יותר. הווקטורים מנורמלים (`normalize_embeddings=True` ב-[embeddings.py](tax-copilot/src/embeddings.py)), ולכן ההמרה היא `cos = 1 - L2²/2`. בלי ההמרה מד הדמיון ב-UI יוצג **הפוך**.
3. **`EnsembleRetriever` לא מחזיר ציונים** — במצב hybrid השדה `score` הוא `null`, וה-UI מציג דירוג בלבד במקום מד ריק ומטעה.

| Method | Path | |
|---|---|---|
| GET | `/rag/indexes` | `default` + כל `index_custom/*` עם הקונפיג של כל אחד |
| POST | `/rag/indexes/preview` | ספירת צ'אנקים וגבולות — מיידי |
| POST | `/rag/indexes/build` | → `job_id` |
| DELETE | `/rag/indexes/{id}` | `default` חסום ב-400 |
| GET | `/rag/chunks` | דפדוף/דגימה של צ'אנקים |
| POST | `/rag/retrieve` | top-K + score + מטא-דאטה + טקסט מלא |
| POST | `/rag/evaluate-retrieval` | → `job_id`, מחזיר hit@k לפי easy/hard |
| GET | `/rag/jobs/{id}` | סטטוס/phase/done/total |

### 1.3 `api/jobs.py` — תשתית משימות רקע

```python
@dataclass class Job: id, kind, status, phase, done, total, result, error, created_at, cancelled
JOBS: dict[str, Job]                             # בזיכרון — אפליקציה מקומית חד-משתמשית
_EXECUTOR = ThreadPoolExecutor(max_workers=1)    # embedding חסום-CPU; לא לחנוק את המכונה
def submit(kind, fn) -> Job                      # fn(report: Callable[[phase, done, total], None])
def get(job_id) -> Job | None
def cancel(job_id) -> None                       # דגל שה-fn בודק בין פריטים
```

משרתת גם את בניית האינדקס וגם את תיקון כאב ה-UX הגדול בטסט-לאב (מהלך 6).

## מהלך 2 — Backend: מה שעולה קריאות

`api/rag/generation.py` — imports עצלים בתוך הפונקציות בלבד.

| Method | Path | עלות |
|---|---|---|
| POST | `/rag/answer` | `{query, index_id, k}` **או** `{query, chunks:[...]}` לבחירה ידנית — **קריאה 1** |
| POST | `/rag/judge` | `{question, answer, chunks[], reference_answer?}` — **4 קריאות**, ~20 שניות |
| GET | `/rag/quota` | ספירת `llm_calls` היום, פילוח לפי `source` |

- מעביר `question` ל-`judge_faithfulness` — התיקון שכבר קיים ב-[src/judges.py](tax-copilot/src/judges.py) ושלא הוחל רטרואקטיבית על Task 5. ה-UI מסמן את זה: השופט החי מכויל טוב יותר מהמספרים ההיסטוריים שמוצגים ב-`MetricsPanel`.
- `refusal_correctness` בקוד, חינם, כשהשאלה הגיעה ממערך ההערכה.
- **אפס צ'אנקים נבחרו** = תרחיש לגיטימי ומאלף (המערכת חייבת לסרב), לא שגיאה. הכפתור מזהיר ולא חוסם.
- כל קריאה נרשמת ל-`llm_calls` דרך `_common.log_llm_call` עם `source='rag'` ו-`agent_name='rag'|'rag_judge'`. `llm_calls.agent_name` הוא TEXT חופשי בלי FK, ו-`source` בלי CHECK — אין צורך ב-migration; רק לעדכן את הערת התיעוד ב-[schema.sql](tax-copilot/api/db/schema.sql). **לא** להוסיף שורה ל-`agents`: `seed_if_empty` רץ רק על טבלה ריקה, כלומר לא היה נכנס ממילא.

## מהלך 3 — יסודות Frontend (מערכת עיצוב + מעטפת)

נבנה **לפני** הפאנלים, אחרת בונים אותם פעמיים.

### 3.1 ספריות חדשות
`react-router-dom`, `@tanstack/react-query` (מחליף את שלשות `data/loading/error` הידניות, cache בין טאבים, polling ל-jobs, optimistic updates), `recharts`, `sonner`, `lucide-react`.

> לפני שורת קוד ראשונה של גרף — **לטעון את סקיל `dataviz`**. הפלטה והכללים משם, לא מאולתר.

### 3.2 מערכת עיצוב — `web/src/styles/` (מפצל את [index.css](tax-copilot/web/src/index.css))
- `tokens.css`: משטחים, טקסט, סמנטיקה (success/warning/danger/info — כל אחד fg+bg+border; היום `#237a41`/`#a2650f` **מקודדים קשיח** בתוך `.badge`), סקאלת מותג, צללים (היום **אפס** `box-shadow`), רדיוסים, טיפוגרפיה, z-index.
- **Dark mode**: `:root` בהיר → `@media (prefers-color-scheme: dark)` → override ב-`[data-theme="dark"]`, מתג בהדר ב-localStorage.
- **Responsive**: breakpoints 768/1200/1600 (היום **אפס** media queries). `--content-width` ל-1440px; דפי לאב/RAG מקבלים `.app-main--wide`.
- לשמר logical properties (`margin-block-end`, `padding-inline`, `text-align: start`) — זה מה שמחזיק את ה-RTL.

### 3.3 מעטפת ו-`components/ui/`
- `App.jsx` → `AppShell` + `<Routes>`: `/calculator`, `/lab`, `/rag`. הטאב כבר לא ternary, וה-state לא נמחק במעבר טאב.
- ניווט צד ב-≥1200px, טאבים עליונים מתחת.
- פרימיטיבים: `Panel` (כותרת/קיפול/סגירה), `PanelPicker`, `DataTable` (גלילה אופקית, header דביק, מיון, חיפוש — מחליף את ה-`style={{overflowX:'auto'}}` המוטמע), `Field`, `Badge`, `Skeleton`, `EmptyState`, `ProgressBar`, `ConfirmButton`, `CopyButton`, `Drawer`.

### 3.4 הוספה/הורדה של פאנלים (הבקשה המפורשת)
כל פאנל מצהיר `{id, title, defaultVisible}`. `usePanelPrefs(pageId)` שומר ב-localStorage `{visible, collapsed, order}`; `<PanelPicker>` בהדר של כל דף פותח רשימת צ'קבוקסים. חל על **שלושת** הדפים.

## מהלך 4 — דף מעבדת RAG: הפאנלים החינמיים

`web/src/pages/RagLabPage.jsx` + `web/src/components/rag/`. **נקודת הדגמה ראשונה: כל מטלה 3 נראית ב-UI, באפס קריאות LLM.**

- **`CorpusPanel`** — 6 המסמכים: פורמט, נושא, ספירת צ'אנקים, לינק למקור. צ'קבוקס לכל מסמך (מזין את מהלך 5).
- **`EvalSetPanel`** — 34 השאלות ב-`DataTable` עם סינון לפי קטגוריה/קושי/`answerable`, ותוויות ה-evidence. למעלה **בדיקת הכיסוי של Task 2**: 2 multi-hop ✓, 2 unanswerable ✓, 1 negation ✓, 1 identifier ✓ — הדרישה המפורשת של המטלה, מוצגת כמצב ולא כטענה.
- **`BaselinePanel`** — הפילוח בשלושת הדליים (20 סירבו / 10 נכון / 1 חלקי / 3 הזיות) + תשובת הבייסליין לכל שאלה. כולל ההערה על הסטייה המתועדת: `partial` מדווח כדלי נפרד ולא נבלע בתוך "הזיות".
- **`ChunkBrowserPanel`** — **הפאנל שמייצג את "Do not skip the reading" של Task 3.** דפדוף בכל צ'אנקי האינדקס הפעיל, סינון לפי מסמך/פורמט, ודגימה אקראית עם seed. מציג md מול pdf זה לצד זה כדי שנזקי ה-parsing (רווחים נבלעים לפני מספרים, טבלאות שהשתטחו) יהיו **גלויים**, לא מתוארים.
- **`MetricsPanel`** — טבלת easy/hard/ALL + גרף RAG מול בייסליין. מדגיש את הפער בין הפרוסות, את הערת הרעש (n=6 → כל שאלה = 16.7 נקודות אחוז), ואת סך הציטוטים המומצאים שנתפסו בקוד.
- **`PerQuestionPanel`** — 34 שורות ב-`DataTable`. לחיצה → `Drawer` עם שאלה, תשובת ייחוס, בייסליין, RAG, **הצ'אנקים שאוחזרו בפועל**, ונימוקי ארבעת השופטים.
- **`SweepsPanel`** — 12 הקונפיגורציות כגרף מקובץ לפי ציר + טבלה, עם קו בייסליין.
- **`ExperimentsPanel`** — שלוש ההשערות שנרשמו מראש, מה שונה, ודלתאות. `partial`/`missing` מסומנים ככאלה.
- **`AnalysisPanel`** — ממצאי (א)/(ב)/(ג), כולל ההבחנה שב-(ב) לא נמצאה שורה **וזו תוצאה**.

## מהלך 5 — דף מעבדת RAG: אינטראקטיבי

- **`RetrievePanel`** — שאילתה חופשית, טעינת שאלה ממערך ההערכה בקליק, ושלוש שאילתות ה-sanity מ-[build_index.py](tax-copilot/src/build_index.py) `SANITY_QUERIES` כ-presets. מציג top-K כ-`ChunkCard`: דירוג, מד דמיון (אחרי המרת L2), מסמך, עמוד/סעיף, טקסט מלא עם הדגשת מונחי השאלה, ו**צ'קבוקס "כלול בקונטקסט"**. כותרת: "נבחרו 3 מתוך 5".
- **`GroundedAnswerPanel`** — "ענה" שולח **רק את הצ'אנקים המסומנים**. מציג את התשובה כש-`[1]`/`[2]` לחיצים וגוללים לצ'אנק המתאים, את ה-`evidence` המילולי, תג סירוב, ואזהרה אדומה על `hallucinated_citations`/`refusal_mismatch`. כפתור "הפעל 4 שופטים" (עם אזהרת עלות) → ארבע פסיקות + נימוקים; אם השאלה מהמערך — גם `correctness` מול תשובת הייחוס ו-`refusal_correctness`.
- **`IndexConfigPanel`** — מסמכים, chunk size/overlap (עם presets מה-sweep: 500/100, 1000/150, 1500/200), מודל embedding (`multilingual-e5-small` מול `bge-small-en-v1.5`, עם אזהרה שה-hit@k צונח מ-0.969 ל-0.719), top-K, dense מול hybrid+BM25 עם משקל.
  - **"תצוגה מקדימה"** → ספירת צ'אנקים מיידית, בלי embedding.
  - **"בנה אינדקס"** → job + `ProgressBar` חי + בורר אינדקס פעיל. `default` לקריאה בלבד.
  - **"מדוד hit@k"** → job חינמי על 32 השאלות בנות-המענה, והתוצאה נוחתת **על אותו גרף** של 12 שורות ה-sweep. זה סוגר את הלולאה: המשתמש משנה קונפיג ורואה אם הוא שיפר, בלי לשלם.
- **`QuotaMeter`** בהדר — קריאות היום מול 500, ואישור לפני כל פעולה שעולה.
- state ב-URL (`?q=&k=&index=&retriever=`) כדי שאחזור יהיה שחזיר ושיתופי.

`api/client.js` מקבל בלוק `// --- RAG ---` באותו סגנון; הוקים ב-`web/src/hooks/useRagQueries.js`.

### טסט-לאב ([TestLabPage.jsx](tax-copilot/web/src/pages/TestLabPage.jsx))

- סדר מחדש: טופס ההרצה **למעלה**; רוברייק ודאטהסט למטה ומקופלים כברירת מחדל (היום שתי טבלאות ארוכות חוסמות את הפעולה העיקרית).

- `RunHistoryPanel`: שורות נגישות למקלדת (`role="button"`, `tabIndex`, Enter/Space), חיפוש, מיון, ו**השוואת שתי ריצות** זו לצד זו.
- `RunForm`: מונה נבחרים, חיפוש בצ'קליסט, קיבוץ לפי קטגוריה, `useMemo` ל-`runnableAgents` במקום שני `useRef` שמונעים לולאה אינסופית.
- `RubricPanel`: מעקב dirty + "יש שינויים שלא נשמרו"; refetch של ההורה כבר לא דורס טיוטה באמצע עריכה.
- `DatasetPanel`: חיפוש, סינון קטגוריה, `ConfirmButton` למחיקה (היום קליק אחד מוחק בלי אישור).
- כשל טעינת agents כבר לא נבלע בשקט.

### מחשבון ([CalculatorPage.jsx](tax-copilot/web/src/pages/CalculatorPage.jsx))
- `ResultsPanel`: "נטו" כמספר ראשי גדול + פירוט מתחת, במקום עשר שורות זהות.
